# 现有亚克力底盘 + OV5647：支架与单摄像头方案

## 支架（本套替代旧v3摄像头零件）

01 底座与双耳立柱×1：60×45底面，厚4，俯仰轴中心距底座下表面70，总高78。两条4宽、28长绑带槽中心距46，先用扎带穿过底盘原有长槽固定。并不保证匹配某组底盘螺孔；不能压住驱动散热片、导线或电池。

02 俯仰载框×1：配套8厚连接耳，插入双耳8.8间隙。两边3.4孔对齐，M3×25螺栓、垫片及锁紧螺母为候选（购买前实测长度，避免与摄像头/排线相撞）。锁紧到角度不自行下垂即可，不把塑料夹裂。纯打印件在-20至+50度每5度采样没有相交；该范围不是实际相机允许角度，需检查PCB、排线、螺丝和车身。

框体36×34，中央22×20避空，适配约25×24板子的外形假设；不是精确PCB孔安装。相机裸板用4个绑带孔、细尼龙线/合适细绑带和非导电软垫固定板边。背面有元件，必须先确认接触点和避空；必要时加绝缘隔离垫，不能靠压元件固定。不遮镜头、排线座或传感器小排线。若板边无法安全夹持就停用，先测真实孔距改成孔固定。相机镜头朝前、画面不倒转，载框背离视线的一侧放连接耳。

00a、00b各打1个，先试连接耳间隙和M3螺丝，再打01/02。MK4S实际喷嘴及PLA预设，0.20层高、4圈外壁、25%填充起步。底座朝下，载框大平面朝下、耳片朝上。横向3.4孔需看切片短桥，必要时仅孔处局部支撑；清理后试螺丝，勿强拧。先看首层，底座可加brim。

在亚克力车上，先摆前部中央，镜头高于滚刷，使视线可看到刷前区域。70是支架轴高度，不是镜头离桌面高度；加上现有底盘离桌高度、载框和镜头偏移后实测。先临时固定看实际画面，再锁紧。不要预设30度必然可用。

已确认用户相机说明为Arducam B0033 OV5647（25×24标称、固定焦点）。先用真实碎屑在10/20/30/50cm试清晰度，确认能分辨目标。固定焦点近距模糊无法靠算法补救；不建议未确认前拧动有胶固定的镜头。

## 算法目标与边界

单摄像头足够用于平整桌面上的局部目标引导。它不自动提供整桌定位/覆盖、可靠深度、金属材质判断或防跌落。第一版选择颜色鲜明、尺寸一致的纸屑/塑料片作为演示，先调通运动与滚刷，再拓展螺丝、银色金属片等反光目标。

### 1 图像处理

从640×480或320×240开始试速度，不承诺Pi3帧率。固定曝光/白平衡前先稳定光照；是否锁定取决于相机软件及环境。裁掉画面上方背景和机器人/滚刷遮挡区，保留桌面ROI。

对颜色明确的目标：HSV阈值 -> 小核开闭运算 -> 连通区域 -> 按面积、形状和有效ROI过滤 -> 得到候选目标。阈值必须用现场图像调，不提供适用所有桌面的通用HSV数值。检测一个目标连续出现3帧再选中；按同一目标的相近位置关联，避免每帧追不同碎屑。相机随车移动时，不可直接用静止相机的逐像素背景减法。银色金属与桌面相近时，改光照/背景或用标注数据训练检测器；不能凭“亮点”保证检出。

### 2 先用图像闭环，后加毫米定位

初期不必知道精确距离：在画面标记“刷子可收集的区域”和入口中心。目标偏左就右轮更快，偏右反之。画面要先确认没镜像；必须架空或在地面短脉冲验证左右方向。

后续：相机先做内参/畸变标定；在桌面放至少4个不共线已知点，建议更多、覆盖实际工作区。记录图像点与机器人相对桌面坐标，求homography，映射得到(x_right_mm,y_forward_mm)。只在标定覆盖区内使用，用没参与拟合的测量点验证误差。目标应近似落在桌面；高物体及镜头畸变会影响结果。车体俯仰、镜头角度/位置/分辨率变化须重新核对标定。标定点不必一直贴在工作桌面，只要镜头相对车体及桌面高度保持不变。刷子入口坐标也需测量。

### 3 运动状态机

WAIT/STOP -> SEARCH -> ALIGN -> APPROACH -> COLLECT -> VERIFY

- SEARCH：有限次数、低速原地转动，每次停稳拍照；禁止找不到目标就持续前进。没有可靠桌沿检测时只能在地面或有物理边界的测试区运行。
- ALIGN：同一目标横向误差进入刷子入口容许范围再前进，容许范围按刷宽、目标宽度及映射误差预留余量。用慢速差速转动并重新检测，不相信单次开环转角。
- APPROACH：短脉冲前进 -> 停稳 -> 新画面重新定位。目标接近或转向误差增加就减速/停车。进入刷子收集带且仍有效跟踪才可执行收集。
- COLLECT：刷子运行，限定时间的小步推进；时长由轮速/刷子实测决定，不预设秒数和毫米的对应关系。摄像头近处盲区内禁止长距离盲走。
- VERIFY：停车、刷新图像，看原目标是否仍在预期区域。目标消失只能标为“待确认”，可能是遮挡、推出视野或漏检，不能直接计为收集成功。若要可靠成功计数，需要能看见进盒过程、收集盒检测器或人工核验。有限次数重试，失败停车。

任何状态：图像过期/丢失、程序异常或桌沿传感器报警 -> 电机停止。目标丢失时立即停止推进，先重新检测；不以继续前进补偿。控制底层需要命令超时停车机制，不能只靠视觉循环的finally。

### 4 控制符号（假设机器人正向已校准）

e = (目标u - 入口中心u) / (画面宽/2)
turn = clamp(Kp * e, -turn_limit, +turn_limit)
left = forward + turn
right = forward - turn

e>0表示目标在右，左轮更快向右转。以上是逻辑轮速，不是直接GPIO电平；真实电机接线、电机极性、PWM死区和驱动使能需另行验证。转向较大时forward=0，丢失或过期目标时left=right=0。使用小死区抑制左右抖动，Kp从小值开始地面试。

现有底盘看起来有4个TT电机。若确认为左右各两电机同侧一起控制，视觉层仍只输出left/right；必须先核对驱动板型号和电机启动/堵转电流能否支持，不仅凭外形接线。尚未提供真实电机控制脚位，本文不自动控制硬件。

### 5 测试顺序

静态图像找目标 -> 人手左右移动目标看转向指令符号 -> 架空轮子验证方向/超时停车 -> 地面短脉冲对准 -> 地面收集 -> 有限测试区防跌落验证。手机记录至少10次目标对准、收集/失败原因及停止距离，再调整速度。
