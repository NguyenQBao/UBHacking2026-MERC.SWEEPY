# METALSWEEP 联动测试版 · 2026-11-04

本包独立运行，保留之前的检测网页/训练工作台。Pi 4B + OV5647；车轮用已确认的 L298N。刷子电机按实物铭牌为 TSINY TS-25GAH370-20、12V、300rpm（带霍尔编码器，本程序暂不读取编码器）；调速板沿用 CCM6N，是否继续使用待确认。电流等参数尚未实测。默认只模拟输出，不接触 GPIO。

**当前没有训练模型；CCM6N 未确认有 GPIO 控制端，电机工作/启动电流未知。先颜色纸片测试，再车轮测试。默认刷子模式是 CCM6N＋额外干接点继电器，只自动开关，刷速和转向由原旋钮/拨动开关设定。没有继电器时只能手动开刷；不能接电位器线到 GPIO。**

## 1. 本版能做什么

- CSI 摄像头实时识别 → 显示框与方向；有地面标定时显示 X/Y 毫米。
- 浏览器控制左轮、右轮和刷子的有时限脉冲；上电默认停止。
- `--wheels-only` 完全不初始化刷子 GPIO，拒绝自动收集/刷子命令。
- 固定相机地面标定后，运行一次“识别 → 对准 → 接近 → 刷子预转 → 推进 → 刷子收尾 → 停车核验”。
- 独立线程令每个电机动作在租约到期后停止；每段最长1秒，最多连续3段。最终推进时间按“目标前向距离＋入口余量”除以实测车速计算，并受 `sweep_seconds` 上限限制（默认最多0.80秒）。刷子在这3段间持续运行，时序无需等待视觉推理。页面失去焦点请求停止，自动流程也检查操作者心跳、时间/步数上限。Ctrl+C/SIGTERM 停输出。
- 未见目标、丢失关联、标定范围外、过期帧不授权继续走；没有自动绕圈寻物。

**尚未实车验证。** 软件超时不是硬件急停，进程被强杀/系统冻结/驱动板损坏时不保证停机。先在车轮架空、滚刷移开碎物时验证；真实运动阶段使用地面围挡区域。当前没有桌沿/碰撞/堵转检测，不能放在无围挡桌面自动运行。

## 2. 接线：先车轮，后刷子

所有接线断电进行；以下程序数字都是 BCM，不是物理排针号。车轮沿用之前接线：

| Pi BCM | 物理脚 | 已有 L298N |
|---|---:|---|
| 17 | 11 | IN1，左轮方向1 |
| 27 | 13 | IN2，左轮方向2 |
| 18 | 12 | ENA，左轮 PWM |
| 22 | 15 | IN3，右轮方向1 |
| 23 | 16 | IN4，右轮方向2 |
| 19 | 35 | ENB，右轮 PWM |
| GND | 6 | 驱动 GND，共地 |

ENA、ENB 调速跳帽取下。沿用之前的**外接5V逻辑供电方案**时：确认 L298N 的 5V-EN 稳压跳帽已取下，才把 Pi 5V（物理2脚）接模块的 +5V 逻辑输入。不要让两路稳压输出互相顶住；若现有模块丝印/稳压方案不同，先确认，不能照电源端子位置猜。

左边前后两台 TT 电机作为一组、右边两台作为另一组；并联前核对每组启动/堵转总电流及模块实际散热能力。先每路接一台、架空确认“前进”方向，再接同侧另一台。同侧前后轮必须向同一车体方向推；若单个轮反向，交换该电机两根线。整个左/右组反向，可改对应 `invert`，并重启。

**TT 车轮电源按其额定电压；不能因为刷子12V，就给黄色 TT 电机也接12V。Pi 用独立稳压 USB-C 电源；电机不从 Pi 5V 取电。**

### 默认方案：保留 CCM6N，添加继电器做开/关

照片中的6A/180W是控制器标称资料，不是电机堵转电流；“180W”也不能直接解释为12V下可连续180W。暂不据此指定保险丝或继电器容量。选择**输入明确兼容3.3V、启动默认断开、带驱动和线圈续流保护的继电器模块**，其干接点的直流负载/冲击电流额定值覆盖实测需求。不能直接用 GPIO 驱动裸继电器线圈。

```text
Pi GPIO13（物理33脚） → 继电器模块 IN（确认3.3V兼容）
Pi GND               → 模块逻辑 GND（按模块说明）
模块 VCC             → 按模块额定要求供电，不能从 GPIO 信号针取电

12V电源正极 → 合适保险丝 → 实体电源开关 → 继电器 COM
继电器 NO（常开） → CCM6N 电源正极输入
12V电源负极      → CCM6N 电源负极输入
CCM6N 电机输出两端 → 刷子电机
CCM6N 原旋钮/正反转开关保留
```

干接点只切12V电源正极，不把12V引到树莓派；NO而非NC保证继电器释放时断电。干接点隔离方案不需要把电机12V回路负极额外接到 Pi；车轮L298N控制回路仍需共地。由继电器输入侧的具体结构决定其逻辑电源接法，不按模块颜色猜测。

程序默认 `brush_mode="ccm6n_relay"`，使用GPIO13的**数字开/关**，不发送PWM，GPIO24/25不接、不初始化。`relay_active_high=true` 表示高电平有效；若模块资料/实测为低电平有效才改false。先断开12V，只测试继电器和万用表通断，确认程序停止、退出及Pi重启时NO断开，再接CCM6N。相应上/下拉按模块有效电平选择，不能给低电平触发继电器一律加下拉。

机械继电器仅做低频开关，不用它调速；CCM6N电源断开后电容残能、滚刷惯性仍会造成转动，必须实测停止延迟和反复通断的适用性。若断电后刷子迟迟不停，需要调整电路/使用厂家支持的使能驱动，不能靠程序宣称立即制动。

### 备选：替换为独立三信号 H 桥

如果以后使用支持3.3V逻辑、额定电流足够的独立 H 桥，可以将 `brush_mode` 改为 `hbridge`，采用以下约定：

| Pi BCM | 物理脚 | 独立刷子 H 桥（要求支持3.3V逻辑） |
|---|---:|---|
| 24 | 18 | IN1 |
| 25 | 22 | IN2 |
| 13 | 33 | EN/PWM，软件500Hz |
| GND | 6/任意GND | GND |

此表**不是CCM6N接线**。需确认新驱动资料中的接口、逻辑电平、500Hz PWM兼容性和常态关闭电平。其持续/峰值电流必须覆盖刷子的工作/启动电流，并具备适合直流电机的续流保护。单向 MOSFET 模块、BTS7960 等其他接口不能直接套用三信号适配器，需要另做适配。

不能把刷子并到现有车轮 L298N 的任一路，它已经分别给左右轮使用；不能从“300rpm”推定 L298N 足以驱动刷子。GPIO不能直接驱动电机。L298N的ENA/ENB、使用H桥时的刷子使能建议各加约10kΩ下拉；**此下拉建议不套用于低电平有效继电器**。刷子12V电源与车轮供电正极分开，H桥控制逻辑地按要求共地。

## 3. 安装到 Pi（先不接通电机）

Mac 终端，若 Pi 地址仍是 raspberrypi.local：

```bash
scp -r software/metalsweep-control pi@raspberrypi.local:~/
```

Pi 终端：先 Ctrl+C 停止之前 `app.py`/`rpicam-hello`，CSI 摄像头只能让一个程序占用。

```bash
sudo apt update
sudo apt install python3-picamera2 python3-opencv python3-numpy python3-gpiozero python3-lgpio python3-venv
cd ~/metalsweep-control
python3 run.py --hsv 0,220,220
```

在 Pi 的 VNC 浏览器打开 **http://127.0.0.1:8091/**。此时点击按钮仅输出模拟值，轮子和刷子都不会动。

可在 Mac 另一个终端使用 SSH 隧道，减少 Pi 上运行 Chromium 的负担：

```bash
ssh -N -L 8091:127.0.0.1:8091 pi@raspberrypi.local
```

Mac 浏览器也打开 **http://127.0.0.1:8091/**；隧道窗口保持运行。本版不直接对局域网开放运动控制。

`--hsv 0,220,220` 是高饱和红色纸片示例。H=0..179，S/V=0..255；颜色不匹配时调整这三个数并重启。红色模式会把其他相近红色物体也识别出来；分数1只是颜色匹配，**不是模型置信度**。先用纯色背景、一个测试物。画面翻转则在 config.json 将 rotate180 改 true，后续标定也必须使用同一方向。

目前没有标定时只显示框，不能显示可靠毫米距离，也不会运行自动收集。程序不使用之前静态空桌面相减法，避免车一移动就整幅误检。

## 4. 先验证真实车轮

核对前述车轮接线/电压/电流后，编辑 `config.json`，**仅将 `wheel_driver_verified` 改成 true**，保持其他确认项 false。停止模拟程序，再运行：

```bash
python3 run.py --hsv 0,220,220 --hardware --wheels-only
```

架空轮子，逐次点“前进一步”“左转一步”“右转一步”“停止”。默认 PWM22%、前进0.10秒、转向0.07秒，是保守起调值，不能保证每台电机都能起转。若起不来不要让其长时间通电堵住；先检查电源/接线，再小幅调整速度参数。`invert` 只反转该组实际电气方向；摄像头图像不能镜像，否则左右关系改变。

地面上量一个前进脉冲的实际位移 d、一次转向的角度；记录负载和电量。例：0.10秒实走10mm，则该工况约100mm/s。程序 PWM 是占空比，**不是转速/车速**。每次动作量尽量小，最后一段约5–15mm更好；以实测调整 `move_seconds`、`turn_seconds`、`sweep_seconds`。

`forward_mm_per_second` 填同一PWM、相近负载/电量下的实测速度；默认100只是示例。短脉冲加速和较长推进的平均速度可能不同，需用预计推进时长再验证一次。最终推进估计 `t=(Y+entry_margin_mm)/forward_mm_per_second`，入口余量默认10mm；超过 `sweep_seconds`（默认0.80秒）则停车报错，不会强行拉长动作。完成速度验证后才将 `speed_calibration_verified` 改true。不能用未经校准的“PWM22%”直接换算距离。

## 5. 固定摄像头并标定距离

摄像头看向车前方地面，建议从向下35–45°试起，画面底部看得到滚刷前约50–80mm的地面，中心看前方约200–400mm。盒子不能挡住即将收集区域，排线不能跟着轮子/刷子运动。高度/角度/分辨率/镜头或裁切改变都要重做标定。

坐标：**X正值在机器人右侧，Y正值在机器人正前方；原点是滚刷收集入口中心在地面的投影**，不是相机中心或车轴。Y表示相对入口的前向距离，不是镜头到物体的斜距。

1. 机器人停稳，在同一平面用尺子摆6个细标记。`points.example.json` 的 XY 是示例：(-100,50)、(100,50)、(-100,200)、(100,200)、(-100,400)、(100,400)mm。必须按实际可见位置摆放、实际测量；看不到50mm位置就要改支架，否则无法通过这套单相机闭环接近到默认60mm。
2. 网页点“保存无标注原图”，得到 `calibration.jpg`。也可以 Pi 另一个终端：

```bash
cd ~/metalsweep-control
curl http://127.0.0.1:8091/raw.jpg -o calibration.jpg
python3 calibrate.py --image calibration.jpg --points points.example.json --out ground.json
```

3. 出现原图窗口，依次点击屏幕提示的6个 XY 地面标记；U撤销、Esc取消。生成 ground.json。若 config 的 rotate180=true，此命令也加 `--rotate180`（原图已经翻转，不要自行再转图片）。
4. 若不方便点击 OpenCV 窗口，可在网页点画面读取 u,v，填入每个标记的 `uv:[u,v]`，然后加 `--no-gui`；标记应从无框原图定位，注意不可点击检测框边缘代替真实标记。
5. 用**另外3个没有参与拟合的位置**摆测试片，对比尺子实测和显示毫米值。建议近收集区误差先控制在10mm以内；不满足就重做。程序报告拟合残差小并不等于真实距离准确；宽角镜头畸变、地面不平、大物体厚度都会带来误差。

蓝色多边形是标定点覆盖区，目标底边中心在多边形外时不估距、不继续前进。仅适合近似平面上的薄碎屑；框底边中心只是接地点近似，反光金属/不规则碎片需实测。复杂畸变需要先做相机内参标定并让标定图与检测帧使用一致的去畸变处理，本版未实现。

## 6. 刷子和一次收集

默认CCM6N方案：添加并验证继电器接法/触发电平/直流负载能力；原旋钮先低速、拨动开关置正确转向。把 `brush_driver_verified` 改 true。用完整模式架空分别测试轮和刷：

```bash
python3 run.py --hsv 0,220,220 --hardware
```

“刷子短转”通电0.30秒，实际转动时间含板上电延迟/断电惯性。**刷毛与地面接触处的运动方向应朝向集尘盒入口/斜坡**。CCM6N模式方向由原开关设置，程序的 brush.invert 不改变方向；只有替代H桥模式才通过 invert 反转。确认没有干涉后再接触地面，刷毛轻触即可。

铭牌标12V、300rpm。V8橙色主轴直径约30mm，300rpm 的理论圆周速度约0.47m/s；加装刷毛/叶片后外径变大、速度随之增加，过快可能将轻片弹飞；实际转速取决于负载和电源。**CCM6N模式用原旋钮调速，config 的 brush_speed 不调实际速度，任何正数仅代表继电器ON**。备选H桥的初始25% PWM也不等于150rpm。低速无法启动时要查驱动与供电，最终以碎片进盒、不过度弹跳、不堵转为准。

机械上必须形成连续路径：桌面/地面 → 低前唇/斜坡 → 盒内。入口台阶、橙色辊未装刷毛、辊与坡之间缝隙过大，算法都不能补偿。先手动推车/旋钮开刷，确认至少能收集一颗测试片，再做自动。

完成方向验证、独立距离验证，并移到有围挡的平整地面后，将以下设为 true：

```text
directions_verified
ground_calibration_verified
speed_calibration_verified
supervised_clear_floor
```

`half_brush_mm` 改成有效刷宽的一半；`collect_y_mm` 根据实际视野和入口位置调整；`center_tolerance_mm` 初始15。所有值都要实际核对，不能将确认项一键改真绕过验证。运行：

```bash
python3 run.py --hsv 0,220,220 --ground ground.json --hardware
```

保持网页在前台，用一个测试片，点“执行单次收集”。任意时刻空格或停止按钮停全部。看不见目标时停车，须人工重新摆放/重新开始；不会盲目向前寻找。

## 7. 联动算法及当前限制

```text
停车并等待相机/车体稳定
    ↓ 连续3个新帧，同一候选仍存在
候选框底边中心 (u,v) → 地面单应矩阵 H → (X,Y)
    ↓ angle = atan2(X,Y)
偏右 → 左轮前/右轮后短转；偏左反之
    ↓ 每个脉冲后停车、等待0.35秒、重新识别
对准后且 Y>60mm → 前进一个短脉冲 → 重测
    ↓ Y≤60mm 且横向已对准
刷子预转0.35秒 → 刷子保持开、车轮动 (Y+余量)/实测车速 秒 → 车停、刷子继续0.30秒
    ↓
全部停止，人工检查盒子，状态 VERIFY_CONTAINER_MANUALLY
```

这些时间/阈值是初值。例：Y=55mm、入口余量10mm、实测100mm/s，推进0.65秒，整段刷子通电约1.30秒；这不是实车测量结果。收集三段由独立线程计时，刷子保持通电，中间不插入停车观察；这是一小段有上限的盲推，需先验证入口机构/脉冲距离。其余转向/接近步骤连续3帧确认是在**停稳后**进行。最近的有效候选优先，简单邻近中心关联防止突然换目标；它不是带外观特征的跟踪器，密集碎片交叉/遮挡仍可能关联错误，先一次一片。

**“目标从画面消失”不证明进盒。** 可能从侧面弹走、进入相机盲区或漏检。本版不会增加“已收集数量”，也不会自动继续下一颗。后续可在入口增加光电对射/盒内观察或称重确认，并结合前方视野复查。障碍测距传感器不能自动证明薄片已进盒，也不能默认替代向下桌沿传感器。

没有编码器时，PWM/时间受摩擦、电压和载重影响；因此使用分段视觉闭环。没有地面标定则只有左/中/右，无法从未知尺寸碎片的单张图直接算绝对距离。没有桌沿检测则不能实现安全桌面巡航。

## 8. 以后换成训练好的模型

仍在 Mac 训练，Pi 只推理。训练工作台保持 `debris` 单类别；本包仅接受模型类别名含 `debris`，普通 COCO 模型不会识别通用碎屑。

Pi 创建独立环境（Picamera2/GPIO/OpenCV 由系统包提供）：

```bash
cd ~/metalsweep-control
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -r requirements-model.txt
python run.py --model ./best.pt --ground ground.json
```

先不加 `--hardware`，验证检测/动作计划，再接通真实输出。Mac 训练导出的 `*_ncnn_model/` 也可传入 `--model`；Pi 安装对应 ncnn 运行库。导出固定输入尺寸须和 config 的 imgsz 一致（这里默认320），不能直接假定旧640导出模型适合320。本包尚未实测模型推理速度/新模型精度；先测 `processing_ms`，过期帧只会等待，不会延长电机动作；不为追求速度取消超时。

建议现场记录20次单片测试：检测成功次数、对准成功次数、真正进盒次数、平均耗时、误动作次数；分别比较不同材质/大小/光照。检测准确率和收集成功率分开算。模型训练、机电机构和距离标定是三件不同的调试工作。

```bash
python3 -m unittest -v test_control.py test_http.py
```

验证包含状态转移、右/左转符号、失联/过期帧、超时电机停机、GPIO模拟适配器与初始化失败、单次清扫后不虚报成功、仅车轮模式、平面标定及区外拒绝。测试使用模拟输出/合成图像，不能代替电流、刹停距离、扭矩、刷毛和实物打印装配测试。

- L298官方数据表：https://www.st.com/resource/en/datasheet/l298.pdf

- GPIO Zero输出接口：https://gpiozero.readthedocs.io/en/stable/api_output.html
- Pi硬件/GPIO：https://www.raspberrypi.com/documentation/computers/raspberry-pi.html
- OpenCV平面单应性：https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html
- Ultralytics NCNN：https://docs.ultralytics.com/integrations/ncnn/
